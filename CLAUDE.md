# ARCH 540 Project

This is an ARCH 540 architecture school project involving the exploration and development of an interactive digital design tool.

The project direction, scope, design concept, and technical approach may continue to change during the design process.

Do not treat previous ideas, experiments, or implementations as permanent project requirements unless the user explicitly confirms them.

The user has an architecture background but no programming background.

When working with the user:

- Use simple language and avoid unnecessary programming terminology.
- Explain technical decisions in architectural or design language whenever possible.
- Do not expect the user to manually write or debug code.
- Help implement changes directly when appropriate.
- Work incrementally and avoid unnecessarily breaking functioning parts of the project.
- Before making major changes to the project structure or technical approach, explain the implications in simple language.
- Do not invent architectural regulations, building code requirements, planning policies, or numerical values.
- When regulations or code requirements are involved, distinguish verified information from assumptions.
- Treat the project as an evolving design exploration rather than a fixed software specification.
