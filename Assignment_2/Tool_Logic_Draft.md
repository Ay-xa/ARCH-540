# 工具内部逻辑草稿（2026-10-17）

> **范围已更正（2026-10-17 稍后）：** 工具是**社区中心的建筑体块推演工具**，以建筑内部的空间使用为主，室外是渐变的“暴露一端”和延伸。下面的内容主要对应“暴露到半室外”这一端的计算引擎，其余部分（体块里的区域划分、功能自动分配）需要重写，见对话和项目备忘。

这是一份阶段性的梳理，说明工具打算怎么工作、哪些已经定下来、哪些还是暂定、哪些还缺。不是最终规格，随设计推进会改。

**原则：** 数字由程序计算；语言模型负责读卡片、解释结果、提出建议；所有舒适范围和界限必须来自文献，不编造；每个数字都带“来源、地点、季节、活动”标签。

## 一、工具回答什么问题
- “方案 A 比方案 B 好还是差？”
- “冬天这个空间的哪个位置更适合哪种活动？”
- 给设计师做功能决定提供依据。结果用色阶和“可接受时间占比”表达，不显示精确度数（绝对值不可靠，相对比较相对可信）。

## 二、五个步骤怎么工作

### 1. 空间盘点（空间卡）
- **输入：** 为虚构的示例空间填写：天空开敞度、各时刻被遮阳的身体比例、侧向透空率、地面和墙面的材料（反射率）、朝向。
- **状态：** 指标已定（来源：Bouyer、Ladybug SolarCal 的输入）。从几何中取得这些数值的方式未定（手填、还是从 Rhino 模型读取）。

### 2. 按季节评分（条件卡）
对每个季节、每个使用时段的每一小时：
1. 从温哥华天气文件取气温、湿度、风速、太阳辐射、天空红外辐射。
2. **平均辐射温度（Tmrt）：** 用 SolarCal（ladybug_comfort）。Tmrt = 周围表面温度 + 太阳增量 + 长波增量，天空开敞度、遮阳比例、地面反射率决定后两项。
3. **行人高度风速：** 从机场风速折算。
4. **PET：** 用 ladybug_comfort 计算，代谢率和衣着来自活动卡。
5. **UTCI：** 同时计算，作对照。

- **状态：** Tmrt 的方法已读源码并用温哥华天气文件试跑通过。第 3 项和降雨还没有解决（见第四节）。

### 3. 活动需求（活动卡）
- **代谢率（候选值，来源各不相同，使用时跟着阈值来源走）：**
  - 墨尔本：坐 1、站 1.2、走 2 met（自述取自 ASHRAE 55 和 ISO 7730，原表未见）。
  - Zhang（拉萨，按 Compendium of Physical Activities 分类）：轻强度（坐、站）平均 1.65 met，中强度（乒乓球、羽毛球）平均 4.75，高强度（足球、篮球）平均 8.5。
  - pythermalcomfort 库里的“典型任务”表（来源在代码里没写明）：静坐 1.0、站立放松 1.2、走 3.2 km/h 2.0、4.8 km/h 2.6、6.4 km/h 3.8、网球 3.8、篮球 6.3 等。
  - **不一致：** Zhang 的“轻强度”1.65 高于墨尔本的坐 1、站 1.2，高强度 8.5 高于库表里的篮球 6.3。
  - **规则：** 用哪个来源的 PET 阈值，就用同一个来源的代谢率和衣着，不能混用。
  - **提醒：** Zhang 指出热感觉在代谢率变化后约 15–20 分钟才稳定，而我们按小时计算是稳态假设，对短时间的剧烈活动偏离更大。ASHRAE 55 的适用前提是至少停留 15 分钟。
- **衣着：** 按季节取值，来源未找到。
- **PET 舒适带，按活动和季节：** 目前只有示范数据（拉萨 Zhang、香港 Lau、墨尔本 Kenawy）。温哥华的没有。分“舒适”和“可接受”两档，宽度的做法借 Yang 和墨尔本（范围随空间类型和季节变）。
- **风界限，按活动：** 采用 Lawson 的思路。第一版参照多伦多条款：坐 ≤10、站 ≤15、走 ≤20 km/h（GEM），各需达标 80% 的时间。这是多伦多的，温哥华的未找到。
- **心理标记（不改数值，只作说明）：** 这个空间是主动选择来的还是路过的、是否有选择余地、是否靠近自然。
- **使用时段：** 按季节设定（多伦多冬季用 08:00–17:00）。温哥华的未定。

### 4. 配对（打分）
- 对每个“空间 × 活动 × 季节”：统计使用时段内，PET 落入该活动舒适带（或可接受带）的小时占比。风层单独统计，风速不超过界限的时间占比。
- **显示规则（用户 2026-10-17 决定）：** PET 层和风层分别列出，不默认合成一个分数。每个空间附一句“主要受限于：热 / 风 / 两者”。可选的合成图只作总览。理由：热不足靠日照和围合解决，风超标靠挡风解决，合成会看不出该动哪个手法（Bouyer 也提醒 PET 会盖住风的不适）。
- 同时输出 UTCI 的“舒适时间占比”（多伦多的结构）作对照。
- **输出：** 把适配度涂在平面或剖面上；热舒适层、风层、解释层可以分别开关，也可合成一张“综合适配图”。
- **状态：** 结构已定。“适配”达标线暂借多伦多的占比作起点（夏 >65%、冬 >30%、过渡季 >45%，用户同意），必须标明是借用的，找到温哥华的依据后替换。多伦多这些占比是 UTCI 舒适带下的目标，用在 PET 舒适带上并无依据，这一点要在结果旁注明。

### 5. 建议修改，再重新打分
- 做法：修改空间卡的参数（比如加顶棚降低天空开敞度和增加遮阳，加挡风屏降低透空率，换地面材料改反射率），然后重算。
- 语言模型的作用：解释为什么这个位置不适配，提出可尝试的手法。
- **缺：** “工具库”（传统与地域性的调节手法）还没收集；每种手法对参数的改变量也没有来源。到这一步之前要先收集。

## 三、指标的分工（已和用户确认）
- **PET 当主指标**，用来做活动配对。理由：UTCI 在设计上不能按活动调整，库的说明也建议这种情况用 PET。
- **UTCI 当对照**，并借用多伦多的结构：按季节、时段统计“舒适时间占比”。
- 代价：两套阈值要维护，向设计师解释时要多说一句。

## 四、已知的缺口和风险
1. **温哥华本地的舒适阈值：没有。** 第一版只能用示范数据，必须标注来源和地点。阈值做成可替换的输入。
2. **行人高度风速的折算：** 对数风廓线里粗糙度取值差别很大（比值在 0.25 到 0.73 之间），需要选定并标注。机场风速到街道的折算在城市里是否成立，也需要查。
3. **降雨：** 没有任何一篇读过的文献把雨放进舒适指数。温哥华问题的核心缺口。目前的落点：空间卡里加“有没有雨遮”参数，依据温哥华《设计与开发导则》3.1.1（雨篷高 3.0–5.0 m，深度与高度之比约 7:10，见 `01_Research/Vancouver_Documents_Round1.md`）。这只表示“有遮蔽”，不给出雨的舒适阈值。
4. **周围表面温度：** 目前用气温代替，会低估被晒热的地面和墙面的辐射（Bouyer 指出半户外空间里辐射主要来自结构表面）。
5. **PET 库之间的差异：** ladybug_comfort 和 pythermalcomfort 对同一输入差约 1.7℃，原因未查明，需要用 VDI 3787 的算例核对。
6. **没有实测验证。** 只能验证趋势，不能验证数值。
7. **适配达标线：** 占比多少算“适配”，没有来源。
8. **平均辐射温度的简化方法：** 第一版用简化估算，还是一开始就接 Rhino 里的 Ladybug，尚未定。

## 五、已定和未定（2026-10-17）
**已定（用户同意）：**
- 第一版演示用冬季一个下雨日和夏季一个下午。具体日期和小时还没选。降雨不进 PET，演示里只能标出“这一天有雨”，不能说雨的影响已被计算。
- PET 层和风层分别显示。
- 达标线暂借多伦多占比。

**未定：**
- 具体演示日期和小时（要从天气文件里挑，有降水记录的冬季日）。
- Tmrt 的简化细节（周围表面温度先用气温代替是否可接受）。

**已定（补充）：先做本地，最后再考虑自动化。** 顺序：先用手填的空间卡数字跑通“空间卡 → 计算 → 涂色”；同时用 Rhino 里已有的 Ladybug（不经过 Compute）验证几何数字怎么取；最后才决定要不要用 Rhino.Compute 自动化（第六节）。

## 六、Rhino 接入的探索（Rhino.Compute）
- **它是什么：** 一个在后台运行 Rhino 和 Grasshopper 的服务，通过网络请求接收参数、返回结果。Hops 是 Grasshopper 里调用它的插件。本地个人电脑使用不另收费（McNeel 常见问题，来自搜索摘要，未亲自核对），服务器上运行按核心小时计费。
- **这台电脑的现状（我查了文件夹）：** 装有 Rhino 7 和 Rhino 8；Ladybug Tools 已安装（`~/ladybug_tools` 里有 Python 环境）；Rhino 8 的包目录里只有 Rhino-MCP-Platform，没有看到 Hops。搜索时没有打开 Rhino。
- **和现有的 `Rhino_Live_Link` 的区别：** 现有的是在打开的 Rhino 里运行脚本，网页读取几何并移动滑块；Compute 是后台按需求解 Grasshopper，不需要 Rhino 窗口开着。
- **未确认：** Ladybug 的 Grasshopper 组件能不能在 Compute 里无窗口运行（搜索没有结果）。
- **关键判断：** 计算核心（Tmrt、PET、UTCI）是纯 Python，不依赖 Rhino。Rhino 或 Compute 只用来从几何得到空间卡的数字（天空开敞度、各小时遮阳比例）。第一版可以先手填这些数字。
- **试验计划（需要用户同意后才做）：** ① 在 Rhino 8 里装 Hops；② 做一个最小的 Grasshopper 定义，从示例体块算天空开敞度；③ 用 Python 通过 Compute 调用它；④ 看 Ladybug 组件能否无窗口运行。
