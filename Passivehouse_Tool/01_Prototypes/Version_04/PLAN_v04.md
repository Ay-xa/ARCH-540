# 窗墙比推敲器 Version_04：分区建议（阶段 C）实施记录

日期：2026-09-24。计划见 `../Version_03/PLAN_zoning.md` §8（建议规则）与 §9（验收）。Version_03 定格为阶段 A + B（条件网格 + 自动分区），Version_04 在其基础上加阶段 C。

## 目的

把分区结果反过来用到立面上，形成"立面 → 分区 → 立面"的闭环，但每一步由用户控制：工具看每个立面房间带内的主导功能，用配置表里该功能的区间检查这面窗是否过热、过暗或多余，给出试算过的具体建议；只有点「采纳」才改动参数。

## 改动

- `wwr-tool.html`（从 Version_03 复制后修改）：
  - 表格下方新增「分区建议」区块，每条建议含立面、依据、建议动作、试算后的预计效果（过热频率 / 采光 / 冬季净得热、采纳后该立面后的主导功能），右侧「采纳」按钮。
  - 新增函数 `stripDominant`（房间带内主导功能）、`trial`（只重算一个立面并重新分区）、`zoningAdvice`（规则）、`adoptAdvice`（采纳）、`renderAdvice`。
  - 立面滑块注册处保存 `sync` 句柄（`facSync`），采纳后同步滑块显示；不改任何计算。
  - `render()` 加一处调用；页面底部说明补一句；自检新增 6 项。
- `zoning-config.js`：与 Version_03 相同，未改。

## 规则（不写功能名称，只看配置表里的曲线方向与区间）

| 规则 | 触发 | 建议 |
|---|---|---|
| 1 过热 | 主导功能 `overheat.dir = down`，且该立面高温时段得热 > 容忍区间中点，或过热频率 > 5% | 南向（方位 135–225°）且挑檐 < 1.4 m：挑檐加 0.4 m（0.6–1.5 m）；其他朝向：窗墙比每次减 5%，直到高温时段得热 ≤ 容忍下限或到 15%。只在试算确实降低过热时给出 |
| 2 偏暗 | 主导功能 `daylight.dir = up`，采光 < 该功能满分线，且窗户冬季净得热 > 0 | 窗墙比每次加 5%，直到采光达标、过热频率将超过 5% 或到 60% |
| 3 多余 | 主导功能 `daylight.dir = down`，窗墙比 > 15%，且窗户冬季净失热 | 窗墙比缩到 12%，给出热损失减少量 |

与计划的差异：计划的 R1（卧室过热）和 R4（客厅过热）合并为规则 1，因为两者只是同一规则在不同容忍区间下的表现；计划里"服务区大窗"规则中的"给出热损失减少量"照做。

## 验收结果（默认方案，g = 1 m）

| 验收项 | 结果 |
|---|---|
| 不自动应用 | 连续两次渲染后 `S.f` 不变 ✓ |
| 采纳生效 | 程序采纳第一条（南立面挑檐 0.60 m）后 `S.f.S.oh = 0.6`，其余 11 个参数不变 ✓；界面实际点击「采纳」后滑块显示同步为 0.60 m ✓ |
| 无连锁 | 采纳后再渲染 `S.f` 不变 ✓；建议列表刷新（南立面过热建议消失，出现"采光 2.1% 可加窗墙比到 45%"的新建议，但未被执行） |
| 西立面建议 | 机场站当下：西立面后 75% 为客厅，过热频率 5.5% > 5% → 建议窗墙比 30% → 25%（预计过热频率 2.8%）✓；2080 年：西立面后为客厅，高温时段得热 23 → 建议窗墙比减到 15% ✓ |
| 原表不变 | 数值摘要与 V02 逐字符相同 ✓ |
| 性能 | `zoningAdvice` 5.6 ms（含每条建议一次单立面试算与重新分区） |

机场站当下默认方案的三条建议：南立面挑檐加到 0.60 m（过热频率 10.3% → 2.6%）；西立面窗墙比 30% → 25%（5.5% → 2.8%）；东立面（卧室）窗墙比 20% → 25%（采光 1.8% → 2.3%，过热频率 0.7%）。

## 已知局限

- 建议只动窗墙比或挑檐两个参数，不动窗数、窗头高度或热质量、通风预设。
- "该立面后面"取整条房间带（进深 D），转角格子同时计入两个立面。
- 采纳一条建议后可能出现互相拉锯的新建议（例如加挑檐后采光下降，再建议加窗墙比）。这是真实的设计权衡，工具只显示，不替用户决定。
