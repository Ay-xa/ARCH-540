## 2. 适宜度的显示

### 2.1 底图与第二级选择

- `#layerSeg` 五个按钮：无 / 采光 / 冬季得热 / 夏季过热 / 适宜度。
- 选「适宜度」时右列出现一行「显示：`<select>`」，选项从 `CFG.functions` 生成：`总览`、`客厅`、`卧室`、`服务区`（第四种功能自动出现）。用原生 `<select>`（决定项 1）：功能数量不限，Tab + 方向键即可操作，不需要额外键盘代码。
- 状态 `S.suitView`：`'overview'` 或功能 `key`。切换底图不重置它。

### 2.2 总览视图：领先幅度 → 颜色深浅

每格：颜色 = 平滑后最高分功能的颜色；不透明度按领先幅度 m = 最高分 − 第二高分（0–100 分制）：

```
alpha = 0.10 + 0.50 × clamp(m / 25, 0, 1)
```

- m = 0（并列）→ 0.10：几乎只剩底色，一眼看出"这里两种功能都行"。
- m ≥ 25 → 0.60：与 V05 分区层的 0.55 相当，明确归属。
- 25 分的依据：分数是三条件加权平均，25 分约等于一个条件从"满分"退到"半分"的差距（权重 0.5 左右时），是设计上"明显更适合"的量级；10 分以下视为"多种可能"（一个次要条件的小差异就能翻转）。两个常数写在代码顶部并加注释，可调。
- 图例：每种功能一个色块 + 一条从浅到深的灰阶条「领先幅度 0 → 25 分以上」+ 一句「颜色越浅，越多功能都合适，由设计者决定」。
- 实施记录里报告默认方案下 m < 10 的格子占比（验收项）。

### 2.3 单功能视图

整层对该功能的平滑后分数热力图：该功能颜色，`alpha = 0.06 + 0.80 × s/100`（与条件层同一套映射）；图例：该功能色阶 0 → 100 分。`needsWindow` 功能在房间带以外为 0 分，热力图上自然是空白。

### 2.4 面积反馈（替代面积分配）

- `shares[f]` = 平滑后最高分为 f 的格子面积 / 整层面积。
- 侧栏「功能适宜度」：每种功能一行「客厅 适合面积 **39%**（目标 30–45）」；低于下限标红并写「低于目标」；高于上限不标（配置表里只把它当参考）。
- 设计建议：某功能低于下限时加一条提示（不可采纳，类别 `area-<key>`）：
  「整层适合{客厅}的面积约占 {18}%，低于目标 {30–45}%。{客厅}最看重{采光}；{南立面}房间带对{客厅}的适合度最高（{72} 分），可以从这一侧的窗墙比或挑檐入手。」
  ——"最看重的条件"取该功能权重最高的条件，"适合度最高的房间带"用 `stripMean`，都从配置表和计算结果得出，代码不写功能名或朝向名（决定项 7）。

### 2.5 格子详情

保留：位置、三个条件值、每种功能的原始分数条、解释句。新增一行：「领先幅度（平滑后）：{客厅} {72} 分，次高 {卧室} {60} 分，领先 **12** 分」。解释句改为只解释"自身最高分功能相对次高功能的主因"（V05 第一分支原句式）；若平滑后最高功能 ≠ 自身最高功能，补一句「与周围格子取平均后，{卧室}略高于{客厅}」。去掉「◀ 所属功能」标记（不再有分配）。

## 3. needsWindow 的实现

- 配置表：功能可选字段 `needsWindow: true`，卧室设置；注释引用 BC Housing Design Guidelines 5.4.1.6（每间卧室须有窗）。
- `gridConditions()` 里每格加一个布尔 `c.inStrip = KEYS.some(k => c.d[k] ≤ D + 1e-9)`（房间带 = 距任一外墙 ≤ D）。这一行不改任何现有数值。
- `suitGrid()`：先按 V05 算 `raw` 和平滑 `sm`（**平滑输入不含本规则**，否则房间带边缘格子的平滑分会被内部的 0 拉低，违反"其余格子分数与 V05 一致"）；然后对 `fn.needsWindow && !c.inStrip` 的格子把该功能的 `raw.score`、`sm` 都置 0，`raw.parts` 置 `null` 并记 `raw.noWindow = true`（详情句显示「房间带以外，卧室须有窗：0 分」）。
- 计算代码只读 `needsWindow` 字段，不写功能名。
- 受影响格子 = 房间带以外的格子。默认方案（20 × 12 m，D = 5，g = 1）：x ∈ (−5, 5)、y ∈ (−1, 1) 的 10 × 2 = **20 格**（预计，实施时由自检统计并报告）。这些格子对卧室的分数从 V05 的非零值变为 0；对其他功能不变；其余 220 格所有功能不变。
- 决定项 4：是否把"立面无窗（窗墙比 0）的房间带"也视为无窗。本计划按你的原文只看房间带几何；若要扩展，只需把 `inStrip` 改为只计有窗立面的房间带。

### 4.3 "适合度明显偏低"的判断

对已指定立面 k、功能 f：`m_f = stripMean(k, f)`，`m_best = stripMean(k, stripBest(k))`。判为偏低当满足任一：

1. `m_f < 50`（0–100 分制的半分线，即三条件加权后平均不及格）；
2. `m_best − m_f ≥ 15`（另一功能明显更合适；15 分与 §2.2 的"多种可能"上限 10 分留出余量）。

主因：对房间带内格子取每个条件分数的面积加权平均 `p̄_f(cond)`，与最适合功能 g 比较加权贡献差 `w_f·p̄_f/Σw_f − w_g·p̄_g/Σw_g`，取差值最大（对 f 最不利）的条件——与 `explainCell()` 的主因逻辑相同，只是从单格换成房间带。提示句（不可采纳，类别 `intent-fit`）：
「{西立面}对{卧室}的适合度偏低（平均 {38} 分，这一侧最适合{客厅} {79} 分），主要因为{夏季过热暴露}高（房间带平均 {4.3} kWh/m²，按{卧室}的要求得 {35} 分）。」
两个阈值写为常数并注释（决定项 5）。

## 5. 转角格子

- **适合度计算与统计**：转角格子同时属于两条房间带（与 V04 一致）。`stripMean`、`stripBest`、面积反馈都把它计入两条带；`needsWindow` 只看"是否在任一房间带内"，转角自然在内。
- **房间带图层的着色**：两条带指定了不同功能时，转角方块**沿对角线一分为二**，靠南北立面的一半涂南北带的功能色，靠东西立面的一半涂东西带的功能色（对角线从建筑角点指向内角点，即两条边线的交点）。指定相同功能或只有一条带指定时不分割。功能名文字放在每条带的中段（避开转角）。
- **建议**：每条带的规则只看自己的指定功能，转角格子不影响规则触发（规则用的是立面级指标 hotPer / DF / netPer）。

推荐对角线分割（决定项 6）；备选是两色半透明叠加，但叠色在深色模式下不易辨认。

## 8. 需要你决定的问题

1. **第二级选择与"打算放置"的控件**：原生 `<select>`（推荐：功能数量不限、键盘原生可用、320 px 侧栏放得下），还是按钮组（视觉更一致，但第四种功能起会换行）。
2. **领先幅度映射**：`alpha = 0.10 + 0.50 × min(m/25, 1)`，"多种可能"阈值 10 分（推荐），或改别的常数。
3. **总览与领先幅度用平滑后分数**（推荐，与 V05 分区层同源；格子详情的分数条仍显示原始分并另注平滑后领先幅度），还是全部用原始分（不平滑，可能出现棋盘状）。
4. **needsWindow 的"有窗"**：只看房间带几何（按你原文，推荐本轮如此），还是把窗墙比为 0 的立面的房间带也视为无窗。
5. **"明显偏低"阈值**：平均 < 50 分，或落后最适合功能 ≥ 15 分（推荐）。
6. **转角着色**：对角线分割（推荐）或两色叠加。
7. **面积反馈提示的措辞**：带"最看重的条件 + 最适合的房间带"的配置驱动句（推荐），还是只陈述占比、不给方向。
8. **配置表**：删除 `contiguity`、`minRegion`（推荐）或保留并注释"已停用"。
9. **V05 加一行测试专用导出 `window.__suit`**用于分数逐格比对（推荐；只在自检里赋值），或不动 V05、只在 V06 内做"去掉 needsWindow 后与保留时一致"的自洽测试（这不能证明与 V05 一致）。
10. **解释句**：平滑后最高 ≠ 自身最高时补一句「与周围格子取平均后…」（推荐），或不提平滑。
11. **面积高于上限**：不提示（推荐，配置表说明它只是参考），或也给一条中性提示。

## 实施记录（2026-09-25，先做一版供用户查看；决定项 1–11 全部按推荐执行，其中第 4 项按用户原文只看房间带几何）

**改动。**
- 侧栏：「各立面」标签页移到「气候数据」之后；「室内分区」改「功能适宜度」，显示每种功能的适合面积占比与目标区间（低于下限标红）。
- 每个立面面板顶部新增「这一侧打算放置」原生下拉（未指定 + 配置表各功能，动态生成）和一行参考 / 评价文字。
- 平面底图「分区」改「适宜度」，选中后出现「显示」下拉（总览 / 各功能，动态生成）。总览：最高分功能的颜色，深浅按领先幅度 `alpha = 0.10 + 0.50·min(m/25,1)`；单功能：该功能平滑后分数热力图。图例随视图切换。格子详情去掉「◀」所属标记，加「领先幅度（平滑后）」一行；解释句只解释自身最高分的主因，平滑后最高不同时补一句。
- 删除 `assignZones`（含 balance / icm / cleanup / 面积复核）与 `stripDominant`；新增 `suitGrid`（原始分 + 平滑 + needsWindow 置零 + 最高 / 次高 / 领先幅度 + 面积占比）、`stripMean`、`stripBest`、`intentIdx`、`stripFit`、`intentTips`、`buildSuitSel`、`buildIntentSel`、`leadAlpha`。`trial` 改为返回试算后房间带对指定功能的平均适合度。
- `zoningAdvice` 的主导功能来源改为 `S.intent[k]`，V04 三条规则的触发条件与试算方法不变；未指定的立面不运行规则。新增两类不可采纳提示：指定功能适合度偏低（平均 < 50 或落后最适合功能 ≥ 15 分；主因取让该功能失分最多的条件）、某功能适合面积低于目标下限（配置驱动：最看重的条件 + 适合度最高的房间带）。列表顶部在有未指定立面时显示引导说明。
- 「房间带边线」图层：已指定功能的房间带填该功能色并写名称；转角两侧不同功能时沿对角线一分为二。
- `zoning-config.js`：`area` 注释改为参考目标；删除 `contiguity`、`minRegion`；卧室加 `needsWindow: true`；`version: 2`。
- 界面与说明文字：分区 → 功能适宜度；建议区说明、计算方法说明按新定位重写。
- 自检：改写 14 项、新增 30 项，共 100 项；`uiDigest` 的分区部分改为适合面积占比 + 最高分功能序列，并导出 `window.__suit` 供逐格比对。

**主因算法的一处修正。** 计划 §4.3 写的是"与最适合功能比较加权贡献差"。实施后发现它回答的是"另一功能为什么赢"（2080 年西立面卧室的主因被算成"冬季得热"，因为客厅在冬季得热上权重更高），改为"让指定功能失分最多的条件"（w × (100 − p̄) / Σw 最大者），2080 年西立面卧室的主因正确变为"夏季过热暴露高（房间带平均 37.4 kWh/m²，按卧室的要求得 0 分）"。
