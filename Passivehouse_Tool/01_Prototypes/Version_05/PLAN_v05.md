## 1. 各立面滑块改为标签页

**结构。** `#facs` 内改为：

```html
<div role="tablist" aria-label="各立面" id="facTabs">
  <button role="tab" id="tab-S" aria-controls="pane-S" aria-selected="true" tabindex="0">
    <span class="t-name">南 180°</span><span class="t-wwr">40%</span><span class="t-dot" hidden></span>
  </button> ×4
</div>
<div role="tabpanel" id="pane-S" aria-labelledby="tab-S">…三个滑块…</div> ×4（非当前的加 hidden）
```

四个滑块面板保留现在的四个盒子和 `facSync`，只是同一时间只显示 `S.sel` 对应的那个。滑块本身的代码一行不动。

**标签内容。** `dirName(facAz(k))` + 方位角，如「南 180°」，偏转后随 `render()` 更新；右侧一个小数字显示该立面当前窗墙比（`S.f[k].wwr`，与滑块同步）；若 `ADVICE` 里有该立面的可采纳建议，显示一个小圆点（`--heat` 色）并在 `aria-label` 里加「有建议」。

**同步。** 不新增状态量，仍只用 `S.sel`：
- 点标签：`S.sel = k; render()`。
- 平面图立面点击区、指标表行：现有代码已是 `S.sel = k; render()`，不改。
- `render()` 末尾的 `renderFacs()` 改名 `updateFacTabs()`：按 `S.sel` 设置每个 tab 的 `aria-selected` / `tabindex`（选中 0，其余 −1）、每个面板的 `hidden`，并刷新标签文字与圆点。剖面、详情、表格高亮本来就读 `S.sel`，自然同步。
- 删除 `.fac` 盒子上的 `click` / `focusin` 选中逻辑（面板只显示一个，不再需要）。
- `adoptAdvice(a)`：在 `render()` 之前加 `S.sel = a.k`，采纳后自动切到该立面标签，滑块显示已由 `facSync` 同步。

**键盘。** 标签用 roving tabindex：←/→ 在四个标签间移动并立即选中（自动激活），Home/End 到首尾；标签只建一次、之后只改属性，所以 `render()` 后焦点仍在按下方向键的那个标签上。Tab 键从标签进入当前面板的第一个滑块。

**CSS。** `.tabs`（横排四等分，底边线）、`[role=tab]`（无边框、选中时底部 2 px `--ink` 线、字重 700）、`.t-wwr`（`--num` 字体、`--muted`）、`.t-dot`（6 px 圆点）、`[role=tabpanel]`；焦点样式沿用现有的 `:focus-visible` 规则。

## 3. 独立的「室内分区」面板

### 3.1 方案

新增一个全宽面板放在汇总行之下、平面/剖面之上（分区是主功能，放最前）。面板内两列：左边一个大 SVG 画楼层平面网格，右边一列放图层切换、图例、格子详情，不遮挡网格。原来的 `#plan` 去掉方格图层，只保留罗盘、日照弧线、立面净得失色带、窗线（决定项 2）。

右侧主区新排列（1440 px 宽，主区约 1056 px）：

### 3.2 是否旋转（决定项 1）

**建议不旋转建筑，只转指北针**，理由：
- 建筑平面图的惯例就是建筑正交、指北针随朝向转；格子保持正方对齐，边上的立面名称（「南 180°」）保持水平可读，并随偏转更新，方向信息没有丢失。
- 不旋转时 SVG 的 viewBox 只需包住 20 × 12 m，每格约 33 px；旋转则要按对角线 23.3 m 留空，每格约 28 px，且转到 45° 时四角留白最多。
- 平面与日照方位图仍然旋转建筑，负责表达建筑与太阳的关系；两张图分工不同。

如果你更希望两张图一致，改为旋转也只是给 SVG 组加一个 `rotate(rot)` 并按对角线定 viewBox，格子仍能满足 ≥ 14 px（1440 px 下约 28 px，390 px 下约 14.5 px）。

### 3.3 尺寸

- 面板左列宽 = 主区 1056 − 内边距 28 − 右列 300 − 间距 16 ≈ 712 px；20 m 长边 → 每格 ≈ 33 px（目标 ≥ 14 px）。
- ≤ 1150 px 时右列换到网格下方（与现有 `.drawings` 断点一致）；390 px 手机：SVG 宽约 338 px → 每格 ≈ 15 px，仍满足；右列内容堆在下方。
- viewBox 按 L、W 加四周 1.6 m 留白（放立面标签和指北针）动态设置，不同建筑尺寸都占满宽度。

### 3.4 内容与交互

- SVG：建筑轮廓、方格（沿用 `gridSvg()` 的颜色逻辑，改成按新比例输出）、四条边外侧的立面标签（方向名 + 方位角 + 窗墙比，点击 = 选中该立面，所选立面的边加粗）、窗线（同平面图）、右下角小指北针（箭头按 `S.rot` 旋转）。
- 图层切换按钮组从侧栏移到右列顶部（`#layerSeg` 保留 id，`buildZoning()` / `updateZoning()` 只改挂载位置）。侧栏「室内分区」保留网格尺寸滑块和用途 / 占比信息。
- `#gridLeg`、`#cellBox` 移到右列；格子点击逻辑不变（`S.cell`）。
- 新函数 `renderZonePlan()` 替代 `gridSvg()` 在 `#plan` 里的调用；`gridSvg()` 保留为内部着色函数。

## 4. 合并「分区建议」与「设计提示」为「设计建议」

### 4.1 结构

一个 `section` 内：标题、筛选（两个按钮：全部 / 仅所选立面，`role="radiogroup"`）、一个 `ul#advice`。列表顺序：可采纳项（带按钮，按原优先级）→ 纯提示（按原优先级）。`renderTips()` 改为只返回条目数组（每条带 `k`、`topic`、`action`），不再写 DOM；`renderAdvice()` 负责合并、去重、筛选、写 DOM。全局 `ADVICE` 仍只存可采纳项（自检不受影响）。

### 4.2 去重规则

每条条目标记两样：**问题类别**和**动作**。同一立面上，若已有可采纳项，则删除满足下面任一条件的纯提示：问题类别相同，或动作相同。

| 来源 | 条目 | 问题类别 | 动作 |
|---|---|---|---|
| 建议规则 1 | 怕热功能后的墙过热 | overheat | 南向 overhang，其他 shrink |
| 建议规则 2 | 要光功能后采光不足 | daylight-low | enlarge |
| 建议规则 3 | 不需要光的功能后大窗净失热 | loss | shrink |
| 提示 | 室内 >25 °C 超过判据 / 建议值 | overheat | 南向 overhang，东西向 shrink，其他 shade |
| 提示 | 允许开窗通风可降过热 | overheat-vent | vent |
| 提示 | 中等热质量可降过热 | overheat-mass | mass |
| 提示 | 采光系数 < 2% | daylight-low | enlarge |
| 提示 | 采光 > 5% 且朝阳 | daylight-high | shrink |
| 提示 | 净失热 > 15 kWh/m² 窗 | loss | shrink |
| 提示 | 冬季净得热高、还有放大余地 | opportunity | enlarge |
| 提示 | 窗间墙暗区 | uniformity | more-windows |
| 提示 | 窗框占比高 | frame | fewer-windows |
| 提示 | 挑檐压低采光 | overhang-daylight | raise-head |
| 提示 | 窗墙比放不下 | clamped | — |
| 提示 | 房间进深超过采光进深 / 窗头被限制 | 全局（无立面） | — |

默认方案下的效果：南立面「过热 10.3%」提示与规则 1 的挑檐建议同类，只留带按钮的；西立面同理；东立面「采光 1.8% 低于 2%」与规则 2 同类，只留带按钮的。开窗通风 / 热质量两条子提示类别不同，保留（决定项 7）。

### 4.3 筛选

「仅所选立面」显示 `k === S.sel` 的条目，外加无立面的全局提示（决定项 4）。筛选状态存 `S.tipFilter`（'all' | 'sel'），切换立面时不改筛选。

## 5. 其他小问题

- **剖面角度标注避让。** `beam()` 先算出两条标注的 y（`Y(topY + 0.45)`），若两者相差 < 14 px，把后画的「冬」标注下移 14 px（角度小的在下，与光线位置一致）。只改标注坐标，不改光线。
- **气候按钮。** 界面用短标签映射 `CLIM_SHORT = {apNow:'机场站', hbNow:'港口站', f2080:'2080 年'}`（只在按钮上用，`CLIM` 数据不动）；按钮组下方一行小字：「机场站、港口站为当下典型年；2080 年为机场站按 SSP5-8.5 移位」。汇总行「基准」和 `climInfo` 仍用完整标签，文字不变。按钮加 `white-space:nowrap`。
- **汇总行一行显示（决定项 3）。** 每项改为竖排小卡：标签在上、数字在中、小注在下（小注 11 px，可在卡内换行），≥ 1280 px 时 `flex-wrap:nowrap`；按钮组放在行末，允许在空间不足时单独换行。顺序：整体窗墙比、平均采光系数、窗户冬季净得失、过热频率、体形系数、基准（有则显示）、按钮。文字与数字不变。
- **底部说明改为折叠。** `p.note` 改为 `<details class="methods"><summary>计算方法说明</summary>`，内部六个小标题，把现有句子按主题归入：采光 / 热损失与冬季得热 / 过热模拟 / 室内分区 / 设计建议 / 数据来源与局限。句子原样搬运，不增删改字。

## 8. 需要你决定的问题

1. **分区面板是否旋转建筑**：不旋转、只转指北针（推荐，§3.2），还是与日照图一致旋转建筑。
2. **原平面图里的方格**：全部去掉，只留罗盘、日照弧线、净得失色带和窗线（推荐），还是保留一层很淡的分区底色作呼应。
3. **汇总行形式**：改为竖排小卡（标签 / 数字 / 小注三行，推荐，能在 1280 px 一行放下），还是保留现在的横排、只缩小间距和字号。
4. **「仅所选立面」筛选时**，是否同时显示无立面的全局提示（房间进深、窗头限制）：显示（推荐）或隐藏。
5. **气候按钮短标签**：「机场站 / 港口站 / 2080 年」+ 下方一行小字，可接受？或者你有别的写法。
6. **标签上的窗墙比**：显示当前滑块值（如 40%）还是实际值（放不下时按 90% 计算的 `wwrAct`）。推荐显示滑块值，与面板内滑块一致；实际值在指标表里。
7. **过热的两条子提示**（开窗通风、热质量）：与可采纳的过热建议并存（推荐，它们是不同的对策），还是一并去重。
8. **「所选立面」详情面板的位置**：放在设计建议之下、说明之上单独一行（推荐），还是与设计建议并排两列（1150 px 以上）。
9. **格子键盘操作**：本次不做（验收只要求标签、图层、采纳三项），格子仍需鼠标点击；是否接受。
