## 0. 先回答两个问题

**动态调节好不好展示？** 能展示，但要两步才有意义：先有"过热发生在什么时候"的月 × 钟点热图，再在上面叠一条规则（比如"室外高于 22 °C 的白天关到 20°"），看热图变了多少。引擎逐时模拟已经有每小时的数据，加规则不难；难的是让人一眼看懂"规则"本身——它不是几何，是一张时间表。**建议这一刀不做**，只把月 × 钟点热图做出来（它本身就有用：告诉你问题在夏天下午还是全年），规则留到以后。Radiance 也跟着不做。

**读图接入能自动到什么程度？** 分两档，要先说清：
- **能自动**：上传一张装置的运动分析图 → 模型按 SHADING_RULES.md 的八个问题读出一张参数卡（转动轴、固定边、折角范围、单元宽、板厚、穿孔……）→ 页面显示卡，你改、你确认 → 卡落到**机构库里最接近的条目**上（中轴转动板 / 竖轴折板 / 横轴折板 / 伞式六角），参数进 json → Grasshopper 立刻生成。
- **不能自动**：一种库里没有的运动方式（比如新的折法、新的铰链拓扑）。模型能描述它，但生成三维要写新的几何规则，那一步仍然是我来做（像之前的 Al Bahar 伞）。页面会明确告诉你"这张图最接近 #2，但有两点不同"，然后由你决定按 #2 近似，还是让我加新条目。

## 2. 方案对比（对比 tab）

### 2.1 快照是什么

一个快照 = 当时的 `state.json`（建筑、楼层组、操作、窗、装置设定）+ 当时的 `results`（段、日照、受晒）+ 页面算出来的整栋数字（过热无板 / 有板、采光、视野、各层面积、立面总长）+ 一张平面小图（SVG 直接存）+ 名字和时间。存在浏览器本地（localStorage），也能导出 / 导入 json 文件，便于换电脑或交给我。

### 2.2 怎么存

设计 tab 右上角一个按钮「存为方案」，弹一行让你起名（默认"方案 1、方案 2…"）。快照取当前渲染用的那份数据，不重新算。

### 2.3 怎么比

对比 tab：
- 顶部选 2–4 个快照。
- **总表**：行 = 指标（过热无板 / 有板、采光无板 / 有板、视野、受晒、各层面积、立面总长、单元数），列 = 方案；每格旁边标和第一列的差值，升绿降红按指标方向。
- **平面小图**一排，各自的热力图。
- **立面段对比**：按段名对齐（同名段并排，缺的留空），只列差值超过阈值的段，免得 40 行都看。
- **一句话差异**：模板句，"方案 2 比方案 1 过热低 1.1 个百分点，主要来自 B 边；采光低 0.3；多了 24 m 立面"。

### 2.4 "每个遮阳工具拿来对比"

对比 tab 里一个按钮「四种装置各跑一遍」：以当前设计为底，依次把装置类型换成无 / #0 / #1 / #2 / #3，其余参数不变，每种存一个快照并自动对比。两条路：
- **只用引擎**（秒出）：过热、采光、视野三列立刻有。
- **带 Ladybug**（每种约 10 s）：按钮旁一个勾"连日照一起跑"，页面逐个写 json、等 Grasshopper 写回、再存快照。跑的时候 Rhino 里能看到装置一种种换。

### 2.5 验收

存 3 个快照（无装置 / 竖轴折板 45° / 横轴折板 45°），对比 tab 的总表、小图、段差、一句话都对；导出 json 再导入，内容一致。

## 3. 读图接入（读图 tab）

### 3.1 流程

```
上传图（可多张：静态 + 运动分析）
→ 可选一句描述（"两片板，底边固定，膝盖向外"）
→ 发给模型（Claude，带 SHADING_RULES.md 的八个问题和机构库的四个条目作为对照）
→ 回来一张参数卡 + "最接近的条目" + "不同之处"
→ 页面显示卡：每个字段可改，旁边是模型的依据一句话
→ 你确认 → 两种去向：
   a. 「应用到设计」：按最接近的条目 + 卡上的参数写进 json 的 shading（设计 tab 立刻变）
   b. 「存入机构库」：卡存进 MECHANISMS.md 的候选区（页面写一个 json，我再整理进 md 和 GH 代码）
```

### 3.2 技术

- 模型调用走**本地服务**：`server.py` 加一个 `/vision` 接口，页面把图和问题发给它，它用你电脑上的 API key（放在 `rhino/api_key.txt`，不进 git）去调模型，再把参数卡 json 回给页面。浏览器里不放 key。
- 参数卡的格式沿用 `SHADING_RULES.md` 的卡模板，字段名和 json 的 `shading` 对齐，确认后不用再翻译。
- 读图结果带"置信度"和"依据"（模型在图里看到了什么）。页面显示依据，便于你判断它是不是读错了。
- 没有 key 或断网：tab 仍能用，只是卡要手填。

### 3.3 和机构库的关系

- 四个条目的参数卡作为"对照样本"一起发给模型，让它按同一套语言回答。
- 模型说"不像任何一个"时，页面显示它的描述，按钮变成「交给 Claude 加条目」：把图和描述存到 `02_Rules/inbox/`，我在聊天里接着做新条目（这一步仍然是人在回路）。

### 3.4 验收

用之前的两张图（膝盖折板、Al Bahar）试：读出的卡和库里的条目一致（折角范围、固定边、单元宽的量级），应用后 Grasshopper 生成的和手调的一样。再用一张库里没有的（比如水平百叶）试，页面要正确说"最接近 #0 但轴是横的"。

## 4. 拓扑词汇：错位、分裂（设计 tab）

### 4.1 错位（Shift）

楼层组多两个数：`shift:{x, y}`，整组在平面上平移。文档里的 "Shift"。段、窗、装置、手柄全跟着（手柄仍按第 1 层矩形解释，错位组的手柄点要加偏移）。Ladybug 自动算到悬挑和被盖住的部分。页面：楼层组 tab 里加两个滑块。

### 4.2 分裂（Split）

一个操作 `{type:'split', apply, axis:'x'|'y', pos, gap}`：把楼板沿一条线切成两块，中间留 gap 宽的缝。周界变成两个闭合多边形，每块自己的段（名字加前缀 L/R 或 前/后）。庭院、凹口按"落在哪一块"归属。这是文档里 "Split" 的最小版本。手柄：缝的中心一个点，拖它改位置。

### 4.3 加体块

按用户意见暂缓；数据和手柄的做法已在 PLAN_massing_v02_ops.md §2.4，以后要做时直接按它。

### 4.4 验收

错位：第 3 组 x 错 3 m，Rhino 里悬挑可见，日照里被盖住的裙房屋顶段受晒下降。分裂：沿 x 在 0.5 处切开留 4 m，段数翻倍，两块各自的朝向正确，庭院落在左块仍生效。

## 5. 让工具"会说话"的三件小事（设计 tab）

和第四刀原计划一致，放在 2–4 之后：

1. **折角扫描曲线**：装置卡里一个「扫一遍」按钮，每个立面折角 0–90，画过热 / 采光 / 视野三条线，只用引擎。
2. **月 × 钟点热图**：每段一张 12 × 24 小格，颜色 = 该小时室内高于 25 °C 的频率；引擎的逐时模拟加一个输出即可。
3. **目标与达标**：三个输入（过热 ≤、采光 ≥、视野 ≥，由你设），段表和平面按达标着色，解读说哪几面没达标、差多少。
